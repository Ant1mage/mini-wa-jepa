Chapter 0 · 先认识硬件与张量内存
本章目标：你能说清一次训练为什么占显存，能读懂张量形状，还能区分物理 Batch 与梯度累积。 只需要会 Python 变量、列表和乘法。此页不会启动训练。
1. 从一个数组开始
一张 BEV 是 [4,128,128] 的 uint8 数组，占 4×128×128=65,536 字节，即 64 KiB。 若转换为 FP32，占用变成四倍。训练还要保存中间激活、梯度、参数和优化器状态， 因此不能只用输入数组大小估计训练峰值。GiB 是 2³⁰ 字节，GB 是 10⁹ 字节，两者不要直接混用。
先认识这些词
术语	用初学者能理解的话解释
张量 Tensor	带形状和数据类型的多维数组。
Batch B	一次前向和反向同时处理的样本数量。
Token N	把图像分成网格后，每个位置对应的特征向量。
显存峰值	运行中最高的实际显存占用，需要前向、反向和同步后测量。
2. 先预测，再拖动
显式注意力分数的形状是 [B,H,N,N]。这里 H=4，N 是 token 数量， 每个数占 s 字节，所以存储量为 。 把 N 从 64 改为 256 时，N 变为 4 倍，你预期存储量会变为几倍？
上方参数控制下面的标记和曲线。这是单层理论示意，不是当前 GPU 的峰值测量； PyTorch SDPA 还可能使用不显式存储完整分数矩阵的实现。
3. 当前计算结果
物理 Batch 33，累积 1 次， 每次参数更新累计 33 个样本； 示意矩阵占 2.062 MiB。
这张图是怎样算出来的？
下面是当前实验实际调用的函数，可以对照中文注释逐行阅读。
def compute(values):
    """只估算一层显式注意力分数的存储量，不能代替峰值显存实测。"""
    batch, tokens = int(values["batch"]), int(values["tokens"])
    heads, element_bytes = 4, int(values["bytes"])
    # 一个 head 中，每个 token 都要与 N 个 token 计算关联：N × N。
    elements = batch * heads * tokens * tokens
    score_mib = elements * element_bytes / 2**20
    # 梯度累积只改变何时更新参数，不会让单次前向看到更多样本。
    effective_batch = batch * int(values["accum"])
    batches = np.arange(1, 129)
    curve = batches * heads * tokens**2 * element_bytes / 2**20
    return dict(score_mib=score_mib, effective_batch=effective_batch,
                batches=batches, curve=curve)

4. 为什么累积不等同于更大的物理 Batch？
loss / accum 后反向传播，再每隔 accum 步更新参数，是常见的累积方式。 但 VICReg 要在同一次前向的样本集合中估计方差和协方差； Batch 16 累积 4 次，不能直接替代 Batch 64 的这些统计量。末尾不足 accum 步时还需正确缩放。
