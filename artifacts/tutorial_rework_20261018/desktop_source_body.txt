Chapter 1 · 把驾驶场景变成 BEV 数组
本章目标：知道一个像素存什么，能手算车辆在图上的位置，并检查坐标方向。 先修：Python 数组索引、Chapter 0 的形状和 dtype。
1. 先看“鸟瞰图”是什么意思
BEV（Bird's Eye View）是从上向下看的空间栅格。本项目用 128×128 像素覆盖 64×64 米， 因此每个像素的间距是 0.5 米。与透视相机相比，远处和近处采用相同的米/像素比例。 这里使用的是模拟器语义真值，并不意味着现实中的相机也能无误差地产生这种地图。
先认识这些词
术语	用初学者能理解的话解释
CHW	通道 Channel、行 Height、列 Width，索引顺序为 bev[c,v,u]。
uint8	一个数占 1 字节，范围 0~255；这里 255 通常表示存在。
语义通道	每层数组只表达一类信息；不同通道可以重叠。
自车坐标系	以当前车辆为原点，x 向前、y 向左，单位是米。
2. 按正式数据解释四个通道
索引	当前正式数据的含义	不要混淆
0	道路、斑马线、车道线	没有独立车道线通道
1	人行道、围栏、交通标志	不是动态车辆
2	其他车、行人等交通参与者	已排除自车
3	可见性，255 可见、0 不可见	不是自车形状
绿色十字是显示叠加的自车标记，未写入模型的交通参与者通道。

4. 上方滑块驱动的合成场景
当前目标 x=12.5m, y=-2.0m， 像素为 u=67.5, v=38.5。 反变换得到 [12.5, -2.0] 米。黄色箭头是目标朝向。
这张图是怎样算出来的？
下面是当前实验实际调用的函数，可以对照中文注释逐行阅读；np 等名称来自本章模块顶部的导入。
def compute(values):
    """同一组物理坐标同时驱动 BEV 中的车辆位置、箭头和坐标读数。"""
    point = np.array([[values["x"], values["y"]]], dtype=float)
    # 物理坐标 x 向前、y 向左；像素坐标 u 向右、v 向下。
    pixel = ego_to_pixels(point)[0]
    theta = np.deg2rad(values["heading"])
    arrow_end = point + 3 * np.array([[np.cos(theta), np.sin(theta)]])
    # 使用同一个几何转换函数画箭头，避免显示方向和坐标读数矛盾。
    arrow_pixel = ego_to_pixels(arrow_end)[0]
    bev = bev_scene(values["x"], values["y"], values["road_width"])
    restored = pixels_to_ego(pixel)
    return dict(bev=bev, pixel=pixel, arrow_pixel=arrow_pixel, restored=restored)

在项目根目录的 Python 环境中，可以这样单独运行这个计算：
from chapters.chapter1_bev.ui import make_controls, compute

values = make_controls().value  # 取得默认实验参数
result = compute(values)       # 只计算，不启动训练或模拟器
print(result.keys())           # 查看返回了哪些数组和指标

5. 自己验证一次
把 x、y 都设为 0：目标是否位于中心？x 改为 10 时，v 应为 43.5。
y 改为 +5：车向左移动，u 应减少 10。方向相反时先查符号，不要调整模型。
只转 heading：车的位置应不变，只有箭头旋转。改道路宽度：只改变道路与两侧边界。
常见错误：把 bev[c,v,u] 写成 bev[c,u,v]；使用 origin="lower" 后仍按左上角公式理解图； 把不可见的 0 当成“已确认没有障碍物”。
