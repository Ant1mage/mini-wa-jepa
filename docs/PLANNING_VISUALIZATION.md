## 面向普通观看者

主交付是中文交互式学习场景；先展示具体问题和可操作对象，逐步解释观察到的变化。
播放、暂停、单步和时间拖动用于有时间过程的内容；其他内容使用拖动对象、图层切换、局部高亮等交互。
真实现场与简化地图按教学问题选用，不强制三维画面为主；代码配中文注释按需展开。
具体各章方案与研究依据见 [交互教材方案](INTERACTIVE_LEARNING_DESIGN.md)；实际章节入口见根目录 `app.py`，阶段7回放的来源与限制见 `chapter7_candidate_planning/README.md`。
RerunLogger、TensorBoard、Marimo 报告继续用于可追溯记录和研究诊断，不能作为面向普通人的主要演示界面。

既有阶段的教学问题分别包括：阶段1如何将环境表示为BEV，阶段2怎样从示范计算误差并学习，
阶段3如何避免表征塌缩，阶段4如何联合学习并形成驾驶流程，阶段5输入缺失意味着什么。
真实记录用于支持这些问题；不能以驾驶回放代替对原理的解释。
阶段3当前只有潜变量预测，无法直接画出可信的未来车辆/道路，需要另行验证可读输出；原理动画必须标为示意。

此前制作的真实视频样片保留为历史证据，不作为最新教学需求的完成证明：`artifacts/public_driving_demo_002/driving_demo.mp4`。
两段来自同一个保留种子的正常/强遮挡真实记录；并非新仿真，不包含多候选选择。

## 单个决策时刻的主画面

- 主场景为实际 BEV；有真实第三人称 RGB 时可放在同一画布侧边，不补造 RGB。
- 同时叠加全部候选轨迹，每条用稳定 ID（A/B/C…）、颜色和未来时刻标记。每个点包含 x/y/v/heading。
- 被选中的候选加粗、加亮、明确标注“本轮执行”；其他候选仍可辨认，不切换成只显示最终一条线。
- 同画布显示各候选已有的未来预测、经过验证的评分分量、最终选择与依据。缺失的评分/风险字段显示未产出。
- 未来参与者/道路几何只有在确有经过验证的输出或解码器时才画；潜变量不能冒充可读未来场景。
- 叠加已实际走过的轨迹和当前车位；预测/选中/实际三个类别使用不同线型并标清来源。

## 交互播放与回放

每轮依次记录当前观测、完整候选集合、各候选预测/评分、selected_id、执行控制与随后实际状态。
车辆前进后，在下一轮相同主视图重画候选与选择，形成可观察的滚动规划过程。
仿真时间、决策步、候选 ID 和选择时间必须一致；交互回放、Rerun 和原始记录来自同一运行。
回放可暂停、单步和拖动时间轴；这些功能不代替独立的模拟器键盘/车辆控制要求。

建议持久字段：

```text
episode_id, sim_time, decision_step
candidates[id]: trajectory[10,4], predicted_future, score_terms, rejection_reason
selected_id, selection_source, executed_action
actual_state, realized_trajectory, future_valid
```

通过 `mini_wa_jepa.visualization.RerunLogger` 扩展公共接口实现，不绕过统一可视化入口。
“模型生成”和“规划器选择”来源应分别标记；不能把手工/脚本选出的候选称为模型自主选中。

## 与阶段的关系

- 阶段4/5：当前正式模型每次输出一条轨迹，没有实际的多候选评分/选择记录。
- 阶段6：验证不同候选的动作后果，把各方案放进统一主画面；采集时的实验指定选择必须如实标注。
- 阶段7：接入候选生成和经过验证的风险/评分与选择器，完整展示选择、执行和下一轮重规划。
- latent 对照、TensorBoard、ADE/FDE、原始数组和验收视频要求继续保留；主视图属于额外交付要求。
